## 1. 요약

세 요청 중 3번은 혼자 설 수 있는 작은 기능입니다. 1번과 2번은 지금 코드가 "10구단 + 우리 구단(+ 12구단 라이벌)"과 "2026년 규칙"을 전제로 짜여 있어서, 시나리오를 얹기 전에 기반 공사가 먼저 필요합니다.

| 요청 | 크기 | 먼저 필요한 기반 |
|---|---|---|
| 3. 포스트시즌 엔트리 | 소 | 없음 |
| 1. 통일 한국 16구단 | 대 | **A. 구단 수 일반화** (일정, 리그 구성, 가을야구, 드래프트 규모, 신생 구단 여럿 동시 창단) |
| 2. 1982 레거시 | 특대 | **A** (6~9구단, 홀수 구단) + **B. 연도별 규칙표** + **C. 구단 계보** (이름·모기업 변경, 해체·인수) |

추천 순서는 **3 → A → 1 → B·C → 2**입니다(5절). 기반 A는 두 시나리오가 함께 쓰므로 한 번만 만듭니다. 통일 한국을 먼저 하면 A가 16구단에서 검증된 뒤 레거시의 작은 리그(6~9구단)에 쓰입니다.

## 3. 공통 기반

### A. 구단 수 일반화 (두 시나리오 공통)

1. **리그 구조를 일반화합니다.** `s.twelve`의 리그 배정 부분을 떼어 `s.leagues`(리그 이름, 소속 구단, 리그별 가을야구 자리)로 옮깁니다. 12구단 라이벌 정보는 그대로 `s.twelve`에 둡니다. 옛 저장은 마이그레이션에서 `s.twelve.leagues`를 옮겨 담습니다.
2. **일정을 일반화합니다.**
   - `seriesPlan`이 아무 맞대결 수(4~22경기)나 2·3연전(필요하면 4연전)으로 나누게 합니다.
   - `pairGames`가 홀수 구단(7, 9, 13…)과 리그 안/밖 경기 수 차이를 받게 합니다. 홀수는 이미 한 팀씩 쉬는 순환(`roundRobin`)이 있으므로 맞대결 수 배분만 일반화하면 됩니다.
   - 16구단 예시(양대 리그 8팀씩, 144경기): 같은 리그 7팀 × 12경기 = 84, 다른 리그 8팀 중 4팀 × 8경기 + 4팀 × 7경기 = 60.
   - 11·12구단 일정은 지금과 똑같이 나와야 합니다(골든 파일로 확인).
3. **가을야구를 일반화합니다.**
   - 리그 수와 리그별 진출 팀 수를 받아 대진을 만듭니다. 시드 배열 8칸 고정을 없앱니다.
   - 레거시용으로 "전후기 우승팀 한국시리즈"(1982~88) 방식을 추가합니다(B의 연도별 방식 표가 고릅니다).
   - 흥행 수익 배분(1.8.4)은 구단 수와 무관하게 이미 경기별이라 그대로 씁니다.
4. **신생 구단을 여럿 동시에 창단합니다.** 특별지명(기존 구단 보호 20명 외 1명씩)을 신생 구단 수만큼 돌립니다. 기존 구단당 잃는 선수 수 상한이 필요합니다(6팀이 1명씩 뽑으면 한 구단이 최대 6명을 잃음).
5. **규모가 구단 수를 따라가게 합니다.**
   - 신인 드래프트 풀(11라운드 × 16 = 176명 지명), 외국인 선수 풀, FA 외부 영입 한도, 2차 드래프트, 중계권 분배, 올스타 편성, 수상 후보 수.
   - 리그 전체 재능 밀도: 구단이 늘면 1군 수준 선수가 묽어집니다. 아마추어 배출 수를 늘릴지(추천), 그대로 두어 리그 수준이 내려가게 할지는 6절에서 정합니다.
6. **화면**: 16행 순위표, 양대 리그 순위표 2개, 대진표(최대 8팀), 휴대폰 폭(390px)에서 가로 스크롤 없이.
7. **성능**: 16구단은 경기 수가 1.6배입니다. 한 시즌 시간과 저장 크기를 재고 1.0 때 정한 한도(PLAN-1.0 §4.B) 안에 드는지 확인합니다.

### B. 연도별 규칙표 (레거시용, 통일 한국에도 무해)

1. `KBO_2026` 옆에 **연도별 규칙표**를 둡니다. 항목마다 `{ from: 연도, 값 }` 계단을 두고, `rulesFor(year)` 하나로 읽습니다. 지금 흩어진 `ruleYear(year) >= 2026 ? …` 분기도 이 표로 옮깁니다.
2. 표에 넣을 항목(게임이 이미 다루는 것만):
   - 리그: 구단 수와 경기 수, 전후기제, 양대 리그(1999~2000), 가을야구 방식과 진출 팀 수, 무승부·연장 규정.
   - 선수단: 1군 등록·출전 인원, 보류(소속) 선수 한도, 육성선수 제도, 퓨처스(2군) 리그 유무.
   - 신인: 1차 지명(연고 지명) 유무와 인원, 2차 지명 라운드, 전면 드래프트.
   - 외국인: 도입 연도, 보유·출전 인원, 계약 상한, 아시아쿼터.
   - 이적: FA 도입 연도와 자격 연수, 보상 규정, 2차 드래프트, 포스팅.
   - 돈: 샐러리캡(2023~), 최저연봉, 중계권, 티켓값(6절 C 참고).
3. **2015년 이후 값은 지금 동작과 같아야 합니다.** 그래야 기존 시나리오와 과거 시즌 생성(2015~)이 바뀌지 않습니다. 첫 단계에서는 골든 파일이 그대로인지로 확인합니다.
4. `era` 시프트와의 관계: 기존 시나리오는 지금처럼 `ruleYear`로 읽고, 레거시는 시프트 0에 실제 연도로 읽습니다. 따로 "역사 모드" 플래그를 둘지, 시프트 0이면 늘 실제 연도로 읽게 할지는 구현하며 정합니다. 둘 다 저장 호환에는 영향이 없습니다.
5. **규칙이 바뀌는 해에 알림**을 띄웁니다. 예: "1998년부터 외국인 선수 2명을 둘 수 있습니다." 겨울(시즌 사이)에 뉴스와 팝업으로 알리고 도움말 연표에도 남깁니다.

## 4. 항목별 계획

### 4.1 포스트시즌 엔트리 (요청 3)

1. **규칙 조사**: KBO 포스트시즌 엔트리 인원(30명으로 알고 있으나 확인 필요), 시리즈마다 교체 가능 여부, 출전 자격(정규시즌 종료 시점 소속 선수, 외국인 대체 선수 등록 마감 8월 15일 등)을 `docs/RULES.md`에 출처와 함께 적습니다.
2. **상태**: `s.postseasonEntry[teamId]` = 시리즈별 선수 id 목록. 시리즈가 끝나면 다음 시리즈 전에 다시 정합니다.
3. **우리 구단**: 시리즈마다 시작 전 결정 화면을 띄웁니다. 기본값은 "지금 1군 + 추천 보강"이고, 투수·야수 수와 외국인 수를 보여 주며, 부상자와 자격 없는 선수는 고를 수 없습니다. 멈춤 설정(1.7)에서 "자동"을 고르면 추천안으로 넘어갑니다.
4. **AI 구단**: 감독 로직(`manager.ts`)으로 투수를 조금 더 넣는 등 가을야구용 엔트리를 짭니다.
5. **경기 엔진**: 가을야구 경기는 1군 대신 엔트리에서 라인업·불펜을 고릅니다. 정규시즌 1군 명단은 건드리지 않고, 가을야구가 끝나면 원래대로 돌아갑니다.
6. **저장**: 가을야구 도중의 옛 저장은 엔트리가 없으면 1군을 엔트리로 씁니다.
7. **시험**: 엔트리 밖 선수가 출전하지 않는지, 부상·자격 규칙, 자동 엔트리가 합리적인지, 옛 저장 불러오기.

### 4.2 통일 한국 16구단 (요청 1)

1. **설정**: 가상의 통일 이후 KBO가 이북 연고 6개 구단을 받아 16구단이 됩니다. 정치적 묘사는 넣지 않고, 야구 리그 확장 이야기로만 다룹니다. 실존 북한 기관·인물·구장 이름(정치적 이름이 붙은 곳)은 쓰지 않습니다.
2. **도시와 구장**: 평양, 남포, 개성, 신의주, 함흥, 원산, 청진 등에서 6곳을 고릅니다. 도시마다 시장 규모, 기본 구장(가상 이름, 좌석 수), 성장 잠재력을 `src/club/cities.ts` 방식(`SCENARIO_CITIES`)으로 정합니다.
3. **구단과 기업**: 이북 신생 구단 6팀(우리 구단 포함인지는 6절)의 가상 이름·색·모기업. 기업은 가상의 이북 기업과 남측 대기업의 북부 진출 구단을 섞되, 실존 기업명은 피하는 것을 추천합니다(1.8.1 '돌아온 탕아'의 현대그룹은 사용자가 지정한 예외).
4. **아마추어**: 이북 지역(예: 평안·황해, 함경·강원 북부)의 가상 고교·대학을 학교 목록에 **별도 층**으로 더합니다(Draft Room 원본은 고치지 않음). 연고 지역이 생기므로 출신 지역 분포에 이북을 넣습니다. 초기엔 인프라가 약해 유망주 수준이 낮고 해마다 올라가게 하는 것을 추천합니다.
5. **리그 구성**: 양대 리그 8팀씩(추천). 남·북으로 나눌지 섞을지는 6절에서 정합니다. 가을야구는 리그별 상위 3팀 + 와일드카드(1.8.1 방식 일반화) 또는 리그별 4팀.
6. **창단**: 2026년 겨울 6팀 동시 창단(A-4). 특별지명, 신인 우선 지명, FA 특례, 외국인 +1 같은 신생 구단 혜택을 6팀에 똑같이 줍니다. 첫해 퓨처스만 뛸지(지금 기본값), 바로 1군일지는 시나리오 설정으로 둡니다.
7. **목표**: 예) 10년 안에 한국시리즈 우승, 또는 이북 구단 중 관중 1위. 실패 조건은 다른 시나리오처럼 기한.
8. **과거 시즌**: 2015~2025년은 지금처럼 10구단으로 만듭니다. 이북 구단은 창단 시점부터 기록이 시작됩니다.

### 4.3 1982년 레거시 (요청 2)

1. **시작**: 1982년 원년. 실제 6구단 + 우리 구단 = 7구단을 추천합니다(6절). 이렇게 하면 실제 창단 흐름을 따라 7 → 8(1986 빙그레) → 9(1991 쌍방울) → 10(2013 NC) → 11(2015 KT)구단이 되어, **지금 게임이 이미 다루는 11구단 상태로 자연스럽게 도착합니다.**
2. **원년 선수단**: 과거 시즌이 없으므로 시뮬레이션 대신 생성합니다. 실업·대학 출신 선수를 출신 지역 연고로 나누던 실제 방식을 본떠 구단마다 선수단을 만들고, 우리 구단도 연고 지역 선수를 받습니다. 선수는 지금처럼 모두 가상 인물입니다(실존 선수 없음).
3. **규칙 변화**: B의 규칙표가 해마다 적용됩니다. 겨울마다 "올해 바뀌는 규칙"을 알립니다. 1차 지명은 연고 지역 고교 출신을 먼저 뽑는 방식으로, 출신 지역 데이터(이미 있음)를 씁니다.
4. **구단 변화**: C의 계보표대로 이름·모기업이 바뀝니다. 우리 구단은 바뀌지 않습니다(모기업 이벤트는 기존 그대로).
5. **돈**: 6절 C에서 정합니다. 추천은 "모든 금액을 지금 가치로" 두고 시장 규모(관중 수요, 중계권)만 연대별 곡선으로 키우는 것입니다. 실제 1982년 금액(연봉 수백만 원)을 쓰면 물가 체계를 새로 만들어야 하고 기존 경제 밸런스(V0.16)를 다시 맞춰야 합니다.
6. **기록 환경**: 1980년대는 완투가 많고 불펜 분업이 약했습니다. 1단계에서는 엔진을 그대로 두고, 감독 성향(선발 투구 수)만 연대별로 조정하는 것을 추천합니다.
7. **긴 플레이**: 1982년에서 2026년까지만 45시즌입니다. 저장 크기, 기록 탭(45년치), 명예의 전당, 은퇴 선수 수가 1.0 때 재던 범위(20시즌)를 넘습니다. 오래된 시즌의 경기 상세를 줄여 저장하는 정리 단계가 필요할 수 있습니다. 먼저 50시즌을 자동으로 돌려 재 봅니다.
8. **목표**: 예) 원년 구단으로 40년 안에 우승 몇 회, 또는 기간 없는 샌드박스. 6절에서 정합니다.

## 6. 결정할 것

추천안은 굵게 표시했습니다. 정해 주시면 2판에 반영합니다.

### A. 버전 나누기
- **단계마다 1.9.x로 냅니다(5절).**
- 모두 끝낸 뒤 1.9.0 하나로 냅니다.

### B. 통일 한국
1. 우리 구단은
   - **이북 신생 6팀 중 하나 (10 + 6 = 16)**
   - 남측 도시 신생 구단 (10 + 이북 5 + 우리 = 16)
2. 리그 구성
   - **양대 리그 8팀씩, 남북 섞어서 배정**
   - 양대 리그를 남부·북부로 나눔(지역 라이벌은 살지만 전력 격차가 리그 격차가 될 수 있음)
   - 단일 리그 16팀(맞대결 9~10경기)
3. 가을야구
   - **리그별 상위 3팀 + 와일드카드(1.8.1 방식)**
   - 리그별 4팀
4. 구단이 늘어난 만큼
   - **아마추어 배출을 늘려 리그 수준 유지**
   - 그대로 두어 리그 수준이 내려감

### C. 1982 레거시
1. 우리 구단은
   - **원년 7번째 구단 (7구단으로 시작, 2015년에 11구단 도착)**
   - 원년 6구단 중 하나를 맡음(예: 삼미)
   - 1980년대 중 창단(예: 1986년 빙그레 자리)
2. 실제 구단 창단·매각
   - **실제 연도대로 고정**
   - 리그 상황에 따라 바뀔 수 있음
3. 돈
   - **모든 금액은 지금 가치. 시장 규모만 연대별로 성장**
   - 실제 당시 금액과 물가
4. 목표
   - 우승 횟수 목표(기간 있음)
   - **기간 없는 샌드박스 + 연대별 업적**

### D. 포스트시즌 엔트리
- **시리즈마다 다시 정함(멈춤 설정 "자동"이면 추천안)**
- 가을야구 시작 때 한 번만

## 8. 위험

| 위험 | 대응 |
|---|---|
| 구단 수 일반화가 기존 11·12구단 게임을 바꿈 | 2단계 골든 파일이 그대로여야 함. 바뀌면 원인을 찾을 때까지 내지 않음 |
| 16구단에서 한 시즌이 느려지고 저장이 커짐 | 2단계에서 재고, 3단계 전에 한도를 넘으면 경기 상세 저장을 줄임 |
| 45시즌 레거시의 저장 크기·화면 속도 | 5단계 시작 전에 50시즌 자동 실행으로 잼 |

| 실제 구단의 과거 이름 사용 | 지금 원칙(PLAN-1.0 §3: 비상업 팬 게임, 로고 없음, 가상임을 밝힘)을 그대로 적용. 가상 구단명 세트에도 연대별 이름을 추가 |
| 통일 설정의 정치적 민감성 | 가상 설정임을 밝히고, 실존 기관·인물·정치적 명칭을 쓰지 않으며, 야구 이야기만 다룸 |
| 홀수 구단 휴식일이 순위 경쟁을 왜곡 | 9구단 시대(2013~14) 실제 방식대로 휴식이 고르게 돌아가는지 시험 |

## 9. 검증

- 단계마다: `npx tsc --noEmit -p .`, `npx vitest run`, `npm run build`, 브라우저 스모크, `npm run -s i18n:check`(critical·major 0), 골든 파일, 옛 저장 fixture 불러오기.
- 2단계: 6~16구단 아무 수로 일정을 만들어 경기 수, 홈·원정 균형, 휴식일을 확인하는 시험.
- 3단계: 16구단 20시즌 자동 실행으로 신생 6팀의 전력·재정이 1.0 난이도 목표 안에 드는지.
- 5단계: 1982~2030 자동 실행으로 규칙 변화가 제때 적용되고 2015년에 11구단, 2026년 규칙에 도착하는지.
