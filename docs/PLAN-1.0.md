# 1.0.0 계획서 (초안)

- 작성: 2026-10-05.
- 기준: main `d78f482` (0.12.0).
- 상태: **검토 대기.** 사용자 확인 전에는 구현하지 않습니다.

## 1. 목표

1.0은 **샌드박스 모드의 완성판**입니다.

- 처음 하는 사람도 튜토리얼과 도움말만으로 창단부터 20시즌 이상 플레이할 수 있어야 합니다.
- 휴대폰에서도 멈춤 없이 돌아가야 합니다.
- 실존 구단명은 화면에서 사라집니다.
- 수백 시드로 밸런스를 검증합니다.
- **새 시스템은 넣지 않습니다.** 1.0은 다듬기·검증·정리만 하고, 새 기능은 1.0 이후로 미룹니다.

## 3. 범위

### A. 구단명 가상화

**바꾸는 것**
- 10개 구단의 이름, 약칭, 색, 모기업 이름.
- 구장명은 기업 이름이 들어간 부분만 바꿉니다.
- 화면 문장에서 실제 구단을 가리키는 표현을 바꿉니다. 예: "NC·KT 선례"는 "앞선 9·10구단"으로 씁니다.
- 테스트의 구단명 표기도 정리합니다.

**유지하는 것** (현실 기반 수치)
- 구단 id: 내부용이라 화면에 나오지 않습니다. 바꾸면 진행 파일 키를 모두 옮겨야 합니다.

### B. 성능·저장

로드맵의 "Worker 시뮬레이션"과 "경기 로그 버리기"는 대부분 이미 되어 있습니다. 남은 문제는 아래 다섯 가지입니다.

1. **자동 저장 비용**
   - 지금은 조작할 때마다 12MB 안팎의 상태를 문자열로 만들어 IndexedDB에 씁니다.
   - 저장은 한 번에 하나만 하고, 대기 중인 저장은 마지막 것만 남깁니다.
   - IndexedDB에는 gzip(`CompressionStream`)으로 압축해 저장합니다. 지원하지 않는 브라우저는 지금처럼 그냥 씁니다.
   - 내보내기 파일은 지금처럼 JSON으로 두고, 불러오기는 두 형식을 모두 받습니다.
2. **은퇴 선수 압축**
   - 은퇴한 지 3시즌이 지난 선수는 숨은 능력, 스카우팅 세부, 아마추어 기록을 지웁니다.
   - 통산 기록, 수상, 경력, 등번호, 프로필 표시에 필요한 요약은 남깁니다.
   - 30시즌 기준으로 상태가 10% 넘게 줄지 않으면 이 항목은 뺍니다(추정 10~17%).
   - 은퇴 1~2년 차 선수는 트라이아웃·방출선수 후보로 다시 쓰이므로 그대로 둡니다(`expansion.ts:172`, `rival.ts:187`).
3. **화면 멈춤**
   - 결정 제출이 오프시즌 단계를 이어서 돌리면 화면 쪽에서 몇 초 걸릴 수 있습니다.
   - Phase 0에서 조작별 최장 작업 시간을 재고, 긴 것은 Worker로 옮깁니다.
4. **리그 생성 시간**
   - 프로파일링으로 상위 병목을 줄입니다. 결과는 바뀌지 않아야 합니다(golden 동일).
   - 과거 시즌 수를 줄이는 방법은 기록실 역사가 얕아지므로 쓰지 않습니다.
5. **iOS 저장 보호**
   - `navigator.storage.persist()`를 요청합니다.
   - 오래 내보내지 않았으면 내보내기를 권하는 알림을 띄웁니다.
   - "홈 화면에 추가" 안내와 최소한의 manifest를 넣습니다. Safari는 오래 방문하지 않은 사이트의 저장소를 지울 수 있습니다(7절 V6).

### C. 난이도

로드맵 설계("AI 판단 정밀도, 협상 수락률, 관측 오차")를 채웁니다. 모두 **우리 구단이 있는 게임에서만** 작동하고, 관전 리그와 golden은 바뀌지 않습니다.

| 축 | 쉬움 | 보통 | 어려움 | 들어갈 곳 |
|---|---|---|---|---|
| 협상 수락률 | FA·연봉·외국인 요구 조금 낮춤 | 지금 그대로 | 조금 높임 | `fa.ts`, `contracts.ts`, `foreign.ts` |
| 관측 오차 | 스카우트 오차 작게 | 그대로 | 크게 | 공개 등급 계산 |
| AI 판단 | AI가 우리 트레이드 제안의 가치를 덜 정확하게 봄 | 그대로 | AI가 트레이드·FA 입찰에서 가치를 더 정확하게 봄 | `trade.ts`, AI FA 입찰 |
| 모기업 인내심 | 신뢰도 하락 완만 | 그대로 | 가파름 | `parent.ts` |

- **보통은 지금과 똑같이 둡니다.** 기존 진행 파일의 체감을 그대로 지키기 위해서입니다. 쉬움·어려움으로 하던 기존 파일은 새 효과가 더해집니다.
- 게임 중에 난이도를 바꿀 수 있게 하고, 바꾼 사실을 구단 연표에 남깁니다(5절 결정 5).
- 효과 크기는 D의 검증 B로 정합니다. 목표는 7절 V8에 있습니다.

### E. 모바일·접근성·다크 모드

**테마**
- 화면 설정에 "시스템 / 밝게 / 어둡게"를 넣습니다.
- 구단색(사용자가 고른 색 포함)이 배경과 대비가 모자라면 강조색을 자동으로 밝게 또는 어둡게 고칩니다. 기준은 글자 4.5:1, 버튼 테두리 3:1입니다.

**키보드·스크린 리더**
- 팝업·결정·선수 창: 포커스 가두기, Esc로 닫기, 닫으면 원래 자리로 포커스 복귀.
- "본문으로 건너뛰기" 링크.
- 진행 상태와 알림 문구는 `aria-live`로 읽어 줍니다.
- 표에 `caption`과 `scope`를 붙입니다.
- 능력치 바처럼 색으로만 구별하는 곳은 숫자나 글자를 함께 보여 줍니다.

**모바일**
- 360px 폭에서 모든 탭이 가로 스크롤 없이 보여야 합니다. 표만 자체 가로 스크롤을 허용하고, 첫 열을 고정합니다.
- 주요 버튼은 터치 영역 44px 이상으로 합니다.
- 입력칸 글자는 16px 이상으로 합니다. iOS가 입력할 때 화면을 확대하지 않게 하기 위해서입니다.
- 노치 영역(safe-area)을 비웁니다.

**글자 크기**: 화면 설정에 작게·보통·크게를 넣습니다.

**자동 점검**

## 4. 단계와 순서

`main`에 머지하면 GitHub Pages로 바로 배포되므로, 단계마다 버전을 올려서 진행 파일 호환을 지킵니다.

| 단계 | 버전 | 내용 | 시뮬레이션 | 완료 기준 |
|---|---|---|---|---|
| 0 | (도구만) | 밸런스·성능 측정 도구, 0.12.0 기준선 보고서 | 변화 없음 | `docs/BALANCE.md`에 기준선, 조작별 최장 작업 시간 표 |
| 1 | 0.13.0 | A 구단명 가상화 | 이름이 상태에 들어가므로 `SIM_VERSION` 올림 (결과 수치는 같음) | 화면 문장·테스트에 실제 구단명 0건(문서의 현실 자료 제외), 이전 진행 파일 이어짐 |
| 2 | 0.14.0 | B 성능·저장 + C 난이도 | 은퇴 선수 압축으로 상태가 바뀜 → 올림. 경기 결과는 같아야 함 | 30시즌 진행 파일 저장 크기 5MB 이하(압축), 자동 저장이 화면을 멈추지 않음, 7절 V7 목표 충족, 보통 난이도 결과 불변 |
| 3 | 0.15.0 | D 대규모 검증과 조정, ⑦ 판정 | 조정하면 올림 | 7절 V8 지표가 모두 범위 안, 200×20에서 예외·멈춤 0 |
| 4 | 0.16.0 | E 모바일·접근성·다크 모드 + F 튜토리얼·도움말 | 변화 없음 | axe 심각·중대 위반 0, 360px 넘침 0, 튜토리얼 테스트 통과 |

**순서를 이렇게 정한 이유**
- 구단명을 먼저 바꿉니다. 이후 보고서, 스크린샷, 테스트가 모두 최종 이름으로 나옵니다.
- 성능은 검증보다 먼저 합니다. 수백 시드 검증이 빨라지고, 압축으로 바뀐 상태도 함께 검증됩니다.
- 난이도는 검증보다 먼저 합니다. 검증 B가 난이도별 효과를 재야 하기 때문입니다.
- UI는 시뮬레이션과 독립이라 뒤에 둡니다. 그래야 마지막 실기기 QA에서 한꺼번에 봅니다.

## 5. 정해 주셔야 할 것 (추천안 포함)

1. **구단명 초안** (3절 A 표): 그대로 / 일부 수정 / 직접 지음.
2. **구장명**
   - 추천: 기업 이름만 빼고 지명으로 바꿉니다(표대로).
   - 다른 방법: 구장명도 모두 가상으로 짓습니다.
3. **기존 진행 파일의 구단명**
   - 추천: 새 이름으로 바꾸고, 지난 기사·알림 문장은 그대로 둡니다.
   - 다른 방법: 기존 파일은 실제 이름을 유지합니다.
4. **버전 방식**
   - 추천: 0.13~0.16을 거쳐 1.0.0으로 갑니다.
   - 다른 방법: 브랜치에서 모두 끝낸 뒤 한 번에 1.0.0으로 머지합니다(PR이 매우 커짐).
5. **게임 중 난이도 변경**
   - 추천: 허용하고 연표에 기록합니다.
   - 다른 방법: 창단 때 고정합니다.
6. **재정 ⑦**: 추천은 검증 데이터를 보고 판정하는 것입니다(3절 D).
7. **실기기 QA**: iOS Safari·Android Chrome 확인을 사용자께서 해 주셔야 합니다(이 환경에서는 불가).
8. **GitHub 릴리스와 태그**: 1.0.0 때 만들지 여부.

## 6. 1.0 이후 버전 정책

- **1.0.x**: 시뮬레이션 결과가 바뀌지 않는 수정만 합니다(golden 같음).
- **1.x**: 시뮬레이션이 바뀌면 `SIM_VERSION`을 올리고 golden을 다시 기록하며, 이전 진행 파일 마이그레이션을 반드시 제공합니다.
- **지원 범위**: 0.8.0 이후 진행 파일은 1.x 동안 계속 이어지게 합니다.
- 1.0.0 릴리스 때 `SIM_VERSION`도 1.0.0으로 맞춥니다. 4~5단계에서 시뮬레이션이 바뀌지 않았다면 0.15.0 → 1.0.0은 이름만 바뀌는 마이그레이션입니다.

### 7.2 가정 (틀리면 계획이 바뀜)

1. **스카우트 추천 자동 결정을 평균적인 플레이어로 본다.**
   - 실제 플레이어는 더 잘하거나 익스플로잇을 씁니다.
   - 그래서 검증 B 결과는 "중간 실력"의 하한으로 읽고, 익스플로잇 점검을 따로 합니다.
2. **보통 난이도는 지금과 같게 둔다.**
   - 0.12.0의 체감이 적절하다는 전제입니다. 피드백에서 너무 쉽거나 어렵다는 말은 없었습니다.
3. **브라우저 속도.** 데스크톱은 Node와 비슷하고, 휴대폰은 2~5배 느리다고 봤습니다. 실측 전까지는 추정입니다.
4. **구단 정보는 `clubs.ts`와 Draft Room `clubs.js` 두 곳에만 있다.**
   - 로드맵 원칙상 그래야 하지만, 문장 템플릿이나 테스트에 하드코딩이 남아 있을 수 있습니다.
5. **재정 ⑦은 지금 데이터 없이 판단할 수 없다.** 그래서 검증 결과에 맡깁니다.
6. **gzip 압축 효과는 진행 파일이 커져도 비슷하다.** 기준선 5배는 5MB 상태에서만 확인했습니다.
7. **리그 이름 "KBO"와 현실 제도는 그대로 둔다.**
   - 로드맵의 가상화 범위는 구단명뿐이고, "현실 KBO 규정 우선"이 게임의 원칙이기 때문입니다.
   - 게임 제목 "KBO 신구단"과 문장 속 "KBO 징계·KBO 이사회"도 그대로입니다.
   - 실존 인물 이름은 코드에서 찾지 못했습니다.
