# KBO 신구단

2026년, KBO 11번째 구단의 초대 단장이 되어 창단부터 우승까지 구단을 키우는 운영 시뮬레이션입니다. 설치·서버 없이 HTML 파일 하나로 실행합니다.

현재 버전은 **0.14.0 (난이도 확장, 압축 저장, 빨라진 리그 생성)**. 1.0까지의 계획은 [`docs/PLAN-1.0.md`](docs/PLAN-1.0.md)에 있습니다. 브라우저에서 바로 플레이: https://mintsiru.github.io/make-a-baseball-team/  2026년 7월 연고지·모기업·구장과 게임 모드(창단부터 퓨처스 1년까지 안내하는 튜토리얼, 또는 바로 1군)를 골라 구단을 창단하고, 트라이아웃·우선지명·특별지명·FA 특례로 선수단을 꾸려 11구단 체제의 1군에 들어갑니다. 그 뒤로는 해마다 신인 드래프트와 계약금 협상, 육성선수 계약, 병역, FA 재계약, 스프링캠프 계획을 정하고, 시즌 중에는 1군 등록·말소와 퓨처스·잔류군 배치를 직접 하거나 감독에게 맡기고, 라인업 카드로 타순·수비 위치·선발 로테이션을 직접 정할 수도 있습니다. 겨울에는 연봉 협상·연봉 조정, FA 협상(선수마다 계약금·연봉·옵션·옵트아웃·약속을 제안하고, 요구 사항이 다른 선수들이 며칠씩 고민하며 경쟁 구단과 저울질하는 11월~1월의 시장, 바로 사인 수준·예산 안 최대 같은 빠른 제안과 상한까지 자동 증액, 계약금 일시불, 등급제·보상선수), 외국인 재계약(다른 구단이 놓아준 KBO 경력 외국인 영입 포함)과 해외 복귀 선수 계약, 격년 2차 드래프트를 치르고, 시즌 중에는 트레이드(7월 31일 마감, 현금·신인 지명권 포함, 리그 전체 선수 찾기)·방출·웨이버·외국인 교체를 하며 경쟁균형세와 외국인 샐러리캡(3명 400만 달러)을 관리합니다. 구단 운영에서는 모기업 목표와 평가, 개막 때 확정되는 모기업 예산과 시즌권(재정 개편 토론은 [`docs/FINANCE.md`](docs/FINANCE.md)), 시즌 결산(입장·중계권·스폰서·상품 / 연봉·스태프·구장), 티켓 가격과 마케팅, 감독·코치·스카우트 등 스태프, 구장 증축·신축을 다룹니다. 경기마다 기록지와 문자중계(처음부터 관전), 한눈에 보는 라인업, 뉴스(경기·이적·결산)·인터뷰·팬 반응, 국가대표(아시안게임·올림픽·WBC·프리미어12·APBC, 차출 제외 요청)·FA·시상·명예의 전당·은퇴 같은 큰일과 우리 구단 기사를 알려 주는 팝업, 시상·기록실·명예의 전당, 구단 연표와 업적이 있고, 여러 선수를 한 번에 정하는 일괄 지정, 화면·게임·구단 이름·저장·AI 기사를 한곳에서 정하는 설정 탭(게임 중 난이도 변경, 능력치 바 색과 표 간격, 기존 10개 구단의 이름·약칭·색·모기업·구장 이름 편집과 가상 이름 세트), 넓은 화면에서 사이드바와 패널로 한눈에 보는 화면이 있고, 부상은 실제 부상 종류와 재활 기간(큰 수술 뒤 병역판정 4급·5급 포함)을, 타자는 주 포지션과 부포지션 0~3개를 가지고, 은퇴하려는 우리 선수는 단장이 설득할 수 있으며, 젊은 선수의 미래 등급은 성적에 따라 시즌 중에도 오르내리고, 등번호를 직접 정할 수 있으며, 드물게 음주운전·도핑(미리 징후가 보임)·폭행·승부조작 같은 사건과 KBO 징계가 생기고, 시민구단은 4년마다 바뀌는 시장을, 명명권 구단은 목표가 다른 스폰서를 만나며, 원하면 본인 API 키로 Claude·GPT·Gemini가 경기 기록을 바탕으로 긴 기사를 다시 씁니다(키는 저장하지 않음). 2026년부터는 모든 구단과 상무가 퓨처스리그를 치르고, 어린 선수는 뛴 만큼 자랍니다. 선수를 미국·일본의 사설 트레이닝 시설에 몇 주씩 연수 보내고(구속·장타·제구 등 시설마다 다름), 실내 연습장·재활센터·데이터 분석실·2군 전용 구장·프리미엄석·전광판 같은 시설을 단계별로 지을 수 있으며, 선수마다 결혼·출산(경조사 휴가)·슬럼프·선행·구설 같은 일이 생기고 팬 호감도가 쌓입니다. 원하면 몇 해 뒤 12번째 구단이 라이벌로 창단합니다: 이름·연고지·운영 성향을 직접 정하고, 특별지명 때 우리 선수를 지켜야 하며, 단일 리그나 1999~2000년 같은 드림·매직 양대 리그로 치릅니다. 구단 없이 리그만 관전할 수도 있습니다. 앞으로의 계획은 [`ROADMAP.md`](ROADMAP.md)에 있습니다.

리그 기록은 2021~2025 실제 KBO 리그 평균에 맞춰 조정했습니다 ([`docs/CALIBRATION.md`](docs/CALIBRATION.md)).

## 실행

```bash
npm ci
npm run build   # dist/index.html 하나가 만들어집니다
```

`dist/index.html`을 브라우저로 열면 됩니다. 개발 중에는 `npm run dev`.

GitHub Pages로 배포하려면 저장소 설정 → Pages → Source를 "GitHub Actions"로 바꾸면, main 브랜치에 올라갈 때마다 `.github/workflows/pages.yml`이 빌드해서 올립니다.

## 테스트

```bash
npm run typecheck
npm test               # 단위·리그·밸런스·golden 테스트 + Draft Room 1.0.1 동일성 테스트
npm run build && npm run test:browser   # 실제 Chromium: 창단부터 1군 진입, 정렬·직접 엔트리 관리까지, 4개 화면 크기
```

밸런스를 바꿀 때:

```bash
npm run calibrate            # 2026 시즌 리그 기록을 2025 실제 값과 비교
npm run report -- seed 2025  # 2015~2025 시즌별 리그 기록·연봉
npx tsx scripts/balance.ts run A 200 20 3   # 관전 리그 200시드 × 20시즌 (결과는 .balance/, 끊겨도 이어 돌림)
npx tsx scripts/balance.ts run B 8 20 3     # 신생구단: 난이도 3 × 모기업 4 × 8시드, 스카우트 추천 결정
npx tsx scripts/balance.ts report           # 결과 표 (docs/BALANCE.md)
# 결과가 바뀌면 src/core/version.ts의 SIM_VERSION을 올린 뒤
npm run golden:write
```

실제 기록 데이터는 `python3 scripts/fetch-kbo-stats.py 2021 2022 2023 2024 2025`로 다시 받을 수 있습니다.

## 원칙

- **숨은 능력과 공개 평가 분리**: 화면·AI·기사는 스카우팅 리포트만 봅니다 (`publicView`).
- **결정성**: 같은 시드와 같은 선택이면 같은 결과. 결과가 바뀌면 `src/core/version.ts`의 `SIM_VERSION`을 올립니다.
- **현실 규정 우선**: 규정 값은 `src/rules/`에만 두고, 근거를 `docs/RULES.md`에 적습니다.

비상업적 팬 제작 게임이며 KBO 및 각 구단과 관련이 없고 승인받지 않았습니다. 구단명·구장명 외의 선수·학교·기록·사건은 모두 가상이고, 2025년까지의 리그 역사도 게임이 만든 가상 역사입니다. 로고와 엠블럼은 쓰지 않으며, 설정 탭에서 구단 이름을 가상 이름 세트로 바꿀 수 있습니다.
